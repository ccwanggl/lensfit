## 2. 功能分级：Must / Should / Could / Won't

### 2.1 Must Have（MVP必须有）

| # | 功能 | 说明 | 竞品覆盖度 |
|---|------|------|:---------:|
| M1 | **跨领域统一工作台** | 用户可在工业/显微/红外三大模式间切换，数据和项目互通 | 0% |
| M2 | **镜头-探测器基础匹配** | 输入部分参数（WD/FOV/focal/传感器），自动计算缺失值并推荐组合 | 70%（但都是单领域）|
| M3 | **传感器-像面覆盖可视化** | 2D图显示传感器矩形与镜头像圆的覆盖关系，渐晕区域高亮 | 0% |
| M4 | **多厂商中立数据库** | 内置Top厂商的主流产品数据，不绑定任何品牌 | <10% |
| M5 | **用户自定义器件** | 当目录中无所需型号时，可手动输入参数参与匹配 | 0% |
| M6 | **项目与方案管理** | 创建项目 → 保存多个候选方案 → 对比 → 导出 | <20% |
| M7 | **接口兼容性检查** | 自动判断镜头与探测器的机械接口是否兼容，是否需要转接环 | 10% |
| M8 | **基础报告导出** | PDF/Excel导出选型结果和参数对比表 | <20% |

### 2.2 Should Have（MVP后快速跟进）

| # | 功能 | 说明 | 竞品覆盖度 |
|---|------|------|:---------:|
| S1 | **奈奎斯特采样匹配** | 分析镜头光学分辨率与传感器采样率是否匹配 | 0% |
| S2 | **多目标优化排序** | 在分辨率、成本、体积、景深之间做Pareto最优推荐 | 0% |
| S3 | **光谱波段匹配** | 红外/多光谱场景下镜头透过率与探测器QE的重叠分析 | 0% |
| S4 | **景深计算与可视化** | 计算近端/远端景深极限，显示清晰成像范围 | <20% |
| S5 | **远心镜头专用计算** | 放大倍率固定、无透视误差的专业计算流程 | <10% |
| S6 | **显微镜C-Mount适配器向导** | 根据物镜倍率+传感器尺寸自动推荐适配器倍率 | 0% |
| S7 | **批量导入器件** | 通过CSV/Excel批量导入厂商产品数据 | 0% |
| S8 | **方案对比雷达图** | 多方案在6-8个维度上的可视化对比 | 0% |

### 2.3 Could Have（中长期规划）

| # | 功能 | 说明 |
|---|------|------|
| C1 | **3D光路预览** | 基于Three.js的简化光路三维展示 |
| C2 | **MTF仿真** | 根据镜头参数估算MTF曲线并与奈奎斯特频率对比 |
| C3 | **噪声预算分析** | 计算系统信噪比，判断是否满足检测信噪比要求 |
| C4 | **价格追踪** | 跟踪器件价格变化，提醒采购时机 |
| C5 | **替代料推荐** | 当某个器件停产时，自动推荐参数最接近的替代型号 |
| C6 | **BOM生成** | 生成完整的光学子系统BOM清单（含转接环、滤光片等） |
| C7 | **团队协作** | 多用户共享项目、评论、审批流程 |
| C8 | **AI辅助选型** | 基于历史选型数据训练推荐模型 |

### 2.4 Won't Have（明确不做）

| # | 功能 | 理由 |
|---|------|------|
| W1 | **完整光学设计（Zemax级）** | 超出产品定位，且已有成熟专业软件 |
| W2 | **镜头加工/制造** | 纯选型软件，不涉及制造环节 |
| W3 | **实时图像采集** | 需要硬件驱动，与选型软件定位不符 |
| W4 | **电商交易功能** | 保持工具中立性，不做交易抽成 |

## 3. MVP 详细范围定义

### 3.1 MVP目标用户

- **主要用户**：机器视觉工程师、光学工程师、系统集成商技术人员
- **使用场景**：新项目启动时快速确定镜头-相机组合；现有项目中替换器件时评估兼容性
- **痛点**：目前需要在3-5个不同厂商网站间切换计算，没有统一工具

### 3.2 MVP功能清单（8周交付）

#### Week 1-2: 基础架构与数据库

| 任务 | 交付物 |
|------|--------|
| 数据库Schema设计与实现 | SQLite数据库 + Alembic迁移 |
| 种子数据录入 | Top 5厂商共~100款镜头 + ~80款相机 |
| 核心光学计算引擎 | ThinLensCalculator + 传感器标准化 |

#### Week 3-4: 工业视觉模块

| 任务 | 交付物 |
|------|--------|
| FA镜头选型流程 | 输入WD/FOV/focal/sensor，计算其余参数 |
| 基础约束检查 | 像面覆盖、接口兼容、WD范围 |
| 结果列表与排序 | 按匹配度评分排序，显示Top 10 |
| 传感器覆盖可视化 | Canvas绘制的传感器+像圆覆盖图 |

#### Week 5-6: 项目管理与UI

| 任务 | 交付物 |
|------|--------|
| 项目CRUD | 创建/编辑/删除项目 |
| 方案保存 | 将选型结果保存为方案，支持多方案 |
| 方案对比 | 表格形式对比2-4个方案的关键参数 |
| 基础报告导出 | Excel导出（PDF延后到Should阶段） |

#### Week 7-8: 集成测试与打磨

| 任务 | 交付物 |
|------|--------|
| 端到端测试 | 覆盖主要用户场景的自动化测试 |
| 性能优化 | 匹配查询<500ms |
| 文档与Demo | 使用说明书 + 录屏Demo |
| Windows安装包 | Tauri打包的桌面应用安装程序 |

## 4. 杀手级功能（Killer Features）

基于竞品分析，以下功能是现有工具完全没有、但工程师强烈需要的**差异化卖点**：

### 4.1 传感器-像面覆盖可视化（KF-1）

**现状痛点**：工程师选型时只能看"像圆≥传感器对角线"的数字，无法直观判断四角渐晕程度。

**解决方案**：
- 实时绘制传感器矩形和镜头像圆
- 渐晕区域用红色半透明标注
- 鼠标悬停显示具体渐晕面积百分比
- 支持旋转传感器90°查看

**用户价值**：避免买到镜头后发现四角发暗的试错成本。

### 4.2 跨领域统一参数体系（KF-2）

**现状痛点**：显微镜工程师和机器视觉工程师使用完全不同的术语和单位。

**解决方案**：
- 统一参数引擎自动转换：
  - 显微镜NA ↔ 工业镜头分辨率
  - 红外IFOV ↔ 可见光像素精度
  - 放大倍率 ↔ 焦距+工作距离
- 用户在任一领域输入的参数，切换到其他领域时自动换算显示

**用户价值**：跨领域项目的工程师无需记忆多套换算公式。

### 4.3 智能缺口检测与补全建议（KF-3）

**现状痛点**：现有工具只计算已知参数，不会告诉用户"你还缺什么信息"。

**解决方案**：
- 当用户输入参数不足以唯一确定系统时，系统提示：
  > "当前参数可确定焦距范围 25-35mm，但无法精确到具体型号。建议补充：
  > 1. 接口类型（C-mount/CS-mount）
  > 2. 最大可接受畸变
  > 3. 预算上限"
- 每个缺失参数标注"重要性权重"

**用户价值**：降低选型门槛，新手工程师也能独立完成。

### 4.4 自定义器件与私有数据库（KF-4）

**现状痛点**：厂商工具只支持自家产品，工程师经常需要匹配非目录内的定制器件。

**解决方案**：
- 一键添加"我的镜头""我的相机"
- 自定义器件参与匹配计算
- 私有数据库加密存储（本地SQLite）
- 支持导入PDF规格书自动提取参数（OCR+LLM）

**用户价值**：真正中立的平台，不受厂商生态绑架。

## 5. 商业化路径建议

### 5.1 免费版 vs 付费版

| 功能 | 免费版 | 专业版（$9.9/月或$99/年）| 企业版（定制）|
|------|:------:|:----------------------:|:-----------:|
| 基础匹配计算 | ✅ | ✅ | ✅ |
| 传感器覆盖可视化 | ✅ | ✅ | ✅ |
| 数据库查询 | 前50结果 | 无限制 | 无限制 + 私有数据 |
| 项目数量 | 3个 | 无限制 | 无限制 + 团队协作 |
| 报告导出(PDF) | 水印版 | 无水印 | 自定义模板 |
| 批量导入 | ❌ | ✅ | ✅ + API |
| 红外/显微镜模块 | 基础版 | 完整版 | 完整版 + 定制 |
| 技术支持 | 社区 | Email | 专属客户经理 |

### 5.2 数据壁垒变现

- **数据API**：向MES/ERP系统提供器件参数查询接口
- **替代料服务**：当器件停产时，付费查询最接近的替代型号
- **价格情报**：订阅特定器件的价格变动提醒

## 6. 风险与应对

| 风险 | 概率 | 影响 | 应对策略 |
|------|:----:|:----:|---------|
| 厂商数据获取困难 | 中 | 高 | 优先从公开PDF规格书入手；建立用户贡献激励机制 |
| 光学计算精度争议 | 中 | 高 | 所有公式标注出处（如EMVA 1288）；提供"理论值"与"实测值"双标注 |
| 竞品快速跟进 | 低 | 中 | 建立社区壁垒（开源部分引擎）；数据更新频率作为护城河 |
| 用户习惯难以改变 | 高 | 中 | 先做极致的单领域体验（工业视觉），再扩展到其他领域 |
| 参数单位混乱导致错误 | 中 | 高 | 强制单位显示（每个数字旁标注单位）；关键计算二次确认弹窗 |
