# 产品定位与路线图（学习优先版）

> 2026-08-24 按 ADR-003 重写。旧版“差异化功能清单与 MVP 范围”（工程师选型定位）作废，其中选型功能描述移至本版第 4 节“实践域”，作为学习实践场景保留。

## 1. 产品定位

**OptiBench 是一个光学学习辅助软件。** 第一要务是帮助学习者（学生、自学者、转行工程师）系统掌握光学：读教程、做实验、沿路径进阶。镜头-传感器选型、器件库、项目管理等工程能力是**学习实践场景**——学习者掌握理论后在真实器件数据上做应用练习。

双层结构（旧：选型主线 + 学习副线）反转为：

```text
学习中心（主线）
  ├─ 课程/路径视图：modules/10→50 学习路径 + 教程正文 + 评测
  ├─ 实验沙盘：19 个 native 实验 + 面包板 preset（自由探索）
  └─ 实践场（原选型工作台）：工业视觉/摄影/显微镜/红外四个实践域
       └─ 匹配引擎、器件 catalog、项目管理（保持不变，作为练习素材）
```

### 目标用户

- **主要用户**：光学/光电专业学生、自学者、需要补齐光学基础的工程师。
- **次要用户**：有选型需求的工程师（使用实践场功能）。
- **使用场景**：按学习路径从基础到光学设计进阶；每个概念配有可交互实验；高阶学习者在实践场完成真实选型项目作为综合练习。

## 2. 功能分级：Must / Should / Could / Won't

### 2.1 Must Have（学习优先 MVP）

| # | 功能 | 说明 | 现状 |
|---|------|------|------|
| LM1 | **内容管道** | 加载 `modules/` markdown 教程（frontmatter 内容合同），engine 内容 API + 前端渲染 | 缺失（modules 是孤儿文档） |
| LM2 | **学习路径图** | 声明式 DAG：概念/实验/preset/实践项目节点 + 先修边；前端路径引导视图 | 缺失（实验 prerequisites 无人消费） |
| LM3 | **学习者状态** | 本地 SQLite 记录进度/测验成绩/实验完成度，无账号系统 | 缺失（仅 localStorage 碎片） |
| LM4 | **学习中心主壳** | 学习中心为默认首页；路径视图 + 沙盘视图；选型收编为实践场入口 | 部分（学习中心是 8 个平级 Tab 之一） |
| LM5 | **实验沙盘** | 19 个 native 实验 + 参数实时调节 + 可视化 | 已有（LearningHub） |
| LM6 | **教程正文补写** | modules/10~50 至少核心概念有可读正文，不再只有大纲 | 缺失（全部 status: draft 大纲） |
| LM7 | **评测** | 通用测验组件，落地 modules/*/assessment 评估标准 | 部分（LearningQuiz 仅限四领域章节） |

### 2.2 Should Have（MVP 后快速跟进）

| # | 功能 | 说明 |
|---|------|------|
| LS1 | **结果分析图表化** | 实验数据 Tab 从 JSON dump 升级为图表（当前 `LearningHub.tsx` 仅 JSON） |
| LS2 | **内容缺口补全** | 反射/平面镜、色散棱镜、菲涅尔衍射、干涉仪、波片、光纤、激光原理等新实验（缺口清单见 repositioning plan） |
| LS3 | **面包板第三 preset** | 薄透镜成像或光栅衍射面包板（沿面包板 next-steps 门禁推进） |
| LS4 | **实践场与路径联动** | 学习路径高阶节点直接打开选型工作台并预置练习参数 |
| LS5 | **学习进度可视化** | 路径图上的完成度标记、掌握度概览 |

### 2.3 Could Have（中长期）

| # | 功能 | 说明 |
|---|------|------|
| LC1 | **通用画布** | 自由拖拽面包板（面包板计划门禁未过前不做） |
| LC2 | **ray-optics 几何层 adapter** | 按 ADR-002 门禁评估 |
| LC3 | **多学习者档案** | 利用 schema 预留的 learner_id 支持切换学习者（仍本地，无账号） |
| LC4 | **AI 导学** | 基于学习路径与进度的答疑/推荐 |
| LC5 | **社区内容贡献** | 用户提交教程/实验预设 |

### 2.4 Won't Have（明确不做）

| # | 功能 | 理由 |
|---|------|------|
| LW1 | **完整光学设计（Zemax 级）** | 超出学习辅助定位 |
| LW2 | **账号系统/云同步** | 本地单用户桌面应用；多学习者用本地档案即可 |
| LW3 | **电商/器件交易** | 保持中立教学定位 |
| LW4 | **实时图像采集** | 需要硬件驱动，与学习定位不符 |

## 3. 实践域（原选型功能，全部保留）

以下能力已存在且不删改，作为学习路径高阶阶段的实践项目素材：

- **匹配引擎**：四级流水线（IndexPreFilter → QuickHardFilter → DomainHardFilter → FullScoring → TOPSIS）+ 可插拔 `DomainModule`。
- **四个实践域**：工业视觉、摄影、显微镜、红外成像工作台。
- **器件 catalog**：SQLite 种子数据（厂商/镜头/探测器）+ 用户自定义器件。
- **项目管理与导出**：项目 CRUD、方案对比、报告导出。

架构约束：学习路径图只能通过 `PracticeActivity` 接口引用上述能力，禁止学习层直接依赖匹配流水线内部实现（见 ADR-003 第 4 节）。

## 5. 风险与应对

| 风险 | 概率 | 影响 | 应对策略 |
|------|:----:|:----:|---------|
| 教程正文补写工作量被低估 | 高 | 高 | 先建内容合同与管道，正文按路径优先级分批补写；核心概念优先 |
| 学习层与选型引擎耦合 | 中 | 高 | `PracticeActivity` 接口隔离 + 依赖方向检查 |
| 定位转换期文档漂移 | 中 | 中 | 本版 roadmap 与 ADR-003 为唯一定位来源；旧文档加注记 |
| 路径图过度设计 | 中 | 中 | KISS：先支持线性路径 + 先修检查，不做掌握度模型 |
