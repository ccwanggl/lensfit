## 一、总体设计原则

### 1.1 重构目标

将 LensFit 从**“按章节编号的线性教材”**（50-learning/00~16）转变为**“按模块组织的微专业环形知识库”**（五模块 + 通用资源 + 综合项目）。

### 1.2 核心约束

| 约束 | 策略 |
|------|------|
| **Obsidian 双链不破坏** | 现有原子笔记（10-concepts/、20-formulas/）保持原位，模块目录通过 MOC（Map of Content）索引链接，而非强制移动文件；如需迁移，使用 `aliases` 保留旧路径可达性 |
| **内容不重复** | 同一份原子笔记不被复制到多个模块；跨模块引用时建立 MOC 链接，必要时用嵌入语法 `![[note]]` |
| **渐进迁移** | 新模块结构先并行搭建，旧结构逐步 deprecate，给双链网络充分适应期 |
| **可执行性** | 每个模块必须具备：入口 README、概念 MOC、公式 MOC、至少 2 个实践项目、自测题库 |

### 1.3 五模块定义

```
┌─────────────────────────────────────────────────────────┐
│                    模块甲｜桥接模块                        │
│         数学/物理/语言最小补齐（折射率、波长、基本术语）      │
│                    ↓ 支撑所有模块                          │
├─────────────────────────────────────────────────────────┤
│  模块乙｜几何光学与一阶成像  →  模块丙｜波动光学与傅里叶成像  │
│  （近轴、成像、孔径、像差）      （干涉、衍射、PSF/OTF/MTF）  │
│         ↓                              ↓                 │
│  ┌──────────────┐              ┌──────────────┐         │
│  │ 模块丁｜光谱学 │ ←────────→ │ 模块戊｜光学设计 │         │
│  │ （色散、光栅、  │   交叉：     │ （闭环、优化、   │         │
│  │  分辨率、仪器） │  MTF/分辨率  │  容差、评价）   │         │
│  └──────────────┘              └──────────────┘         │
│         ↓                              ↓                 │
│              ┌──────────────────┐                       │
│              │   90-综合项目      │                       │
│              │ （单透镜/光谱仪/   │                       │
│              │  MTF对比报告）    │                       │
│              └──────────────────┘                       │
└─────────────────────────────────────────────────────────┘
```

### 2.2 关键设计决策说明

#### 决策1：为什么保留 `10-concepts/` 和 `20-formulas/` 原位，而不是打散到模块？

- **原因**：这两个目录包含 **80+ 和 16+** 个原子笔记，且已被大量 Obsidian 双链引用。强制移动将造成级联式链接断裂。
- **方案**：采用 **“MOC 索引”模式**。每个模块的 `concepts/` 和 `formulas/` 放置 **MOC 索引文件**（Map of Content），用 Obsidian 链接 `[[note]]` 指向原有原子笔记。需要时，模块可以本地补充新原子笔记。
- **收益**：零链接破坏 + 模块视角清晰 + 原子笔记仍保持全局可搜索。

#### 决策2：`50-learning-legacy/` 的定位

- 现有 `50-learning/` 的 17 个章节文件**不移动**，作为“legacy 内容”保留在原位。
- 新模块 README.md 通过链接指向这些文件中的对应章节。
- 当某个章节完全被模块新内容覆盖时，在 `50-learning-legacy/迁移说明.md` 中标注 deprecation 状态。

#### 决策3：模块编号 `10/20/30/40/50` 的含义

- 采用 **10 为步长** 的编号，为将来插入中间模块预留空间（如 25-模块乙深化、35-模块丙专题）。
- 编号递增反映推荐学习顺序，但环形结构允许在模块乙后并行进入模块丙和模块丁。

### 2.3 迁移路径（四阶段）

```
Phase 1: 并行搭建（2-3周）        Phase 2: MOC 填充（2-3周）
├── 创建 00/10/20/30/40/50/90 目录 ├── 每个模块填写 MOC 索引文件
├── 编写各模块 README.md           ├── 从现有内容提取并链接到原子笔记
├── 编写三本账模板和路线文件       ├── 拆分/重组 50-learning 内容到模块视角
├── 编写新增内容（如 4f系统、Czerny-Turner）
│                                  └── 重组习题到各 assessment/
Phase 3: 内容迁移（4-6周）        Phase 4: 旧结构 deprecate（持续）
├── 高价值原子笔记逐步复制到模块目录  ├── 50-learning-legacy/ 中标注替代位置
├── 使用 Obsidian aliases 保留旧链接 ├── 旧版 学习路线.md 顶部添加重定向

└── 整合 cmos_sensor_lab 到模块项目
```

#### 模块丁关键习题

4. 为什么谱仪分辨率不能只靠“加长焦距”来无脑提升？
5. 为什么波长标定是任何实用光谱分析前都必须做的步骤？

#### 模块戊关键习题

1. 为什么真正的光学设计不是“把焦距定出来”就结束？
2. 为什么零基础做设计时最适合从单透镜系统开始？
3. 为什么像差学习既要看“几何图像”，又要看“波前语言”？
